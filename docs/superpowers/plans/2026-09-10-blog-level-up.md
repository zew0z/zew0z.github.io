# Blog "Level Up" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make zew0z.github.io cooler, more fun, and better organized while preserving the gruvbox terminal visual language.

**Architecture:** Vanilla JS + CSS on Jekyll (GitHub Pages). No new dependencies, no framework migration. New JS lives in `assets/js/main.js` (global behaviors) and `assets/js/terminal.js` (guest shell, home only). Post data reaches JS via a Liquid-generated JSON script tag. Signature element: an interactive guest terminal on the homepage that lists real writeups and hides easter eggs.

**Tech Stack:** Jekyll (kramdown, jekyll-seo-tag, jekyll-feed), vanilla CSS (custom properties), vanilla ES5-compatible JS. JetBrains Mono stays as the identity face. Palette stays gruvbox dark, green as primary accent.

**Spec:** User request "make it cooler, more fun, organized and good looking" + memory constraint "keep the gruvbox terminal visual language".

## Global Constraints

- No em-dashes in any new UI copy (use `::`, `-`, or restructure).
- All new motion honors `prefers-reduced-motion` (JS-gated, not just CSS).
- No new external dependencies or font loads.
- Lowercase terminal voice for all new copy; no exclamation marks in system responses.
- Z-index scale: content < 40 (bars) < 60 (crt) < 65 (boot/matrix) < 70 (toast).
- Keep all existing URLs, nav labels, and content untouched.

## Deviations (documented)

- No test framework exists in this static-site repo; TDD is replaced by per-task verification gates: `jekyll build` must succeed and rendered pages must be visually verified (desktop + mobile screenshots) before commit.
- Working directly on `main` matches this repo's established workflow (all previous commits are direct-to-main for this GitHub Pages site).
